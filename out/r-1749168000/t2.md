## Bugs Found

### Bug #1 -- "Search" sidebar click opens command palette instead of navigating (NEEDS MANUAL VERIFICATION)

**Severity**: Major (if confirmed) / Test-artifact (if not)
**Location**: `src/components/Layout.jsx`, sidebar area
**Steps**: Click the "Search" nav item in the sidebar.
**Expected**: Navigate to `/search`.
**Actual**: The command palette opens instead. The URL stays at `/`.
**Root cause analysis**: Two possibilities:
1. **Selector ambiguity (test artifact)**: The Playwright `aside >> text=Search` selector may have matched the "Search or ask..." button (line 106-117 of Layout.jsx) rather than the "Search" NavItem (line 129), since both contain the text "Search". The "Search or ask..." button calls `setPaletteOpen(true)`, which would open the command palette. This is the more likely explanation.
2. **Real shortcut conflict**: The `'/'` keyboard shortcut handler (line 33) might fire during the click event sequence, but this handler calls `navigate('/search')`, not `setPaletteOpen`, so this would not explain the palette opening.
**Confirmed by**: Screenshot `home-04-search-page.png` showing the command palette overlay open after clicking "Search". The Discover nav click (which has no ambiguous text match) worked correctly.
**Verdict**: Likely a test selector issue, not a real app bug. However, the proximity of the "Search or ask..." button to the "Search" nav item in the sidebar could cause real-user mis-clicks. Recommend manual verification.
**Note**: Direct URL navigation to `/search` works correctly (verified in Route Testing).

### Bug #2 -- Nested `<button>` inside `<button>` in KBCard (MAJOR)

**Severity**: Major
**Location**: `src/pages/Home.jsx`, lines 288-299
**Description**: The `KBCard` component renders a delete `<button>` (line 293) inside the outer card `<button>` (line 288). React logs two warnings: "In HTML, `<button>` cannot be a descendant of `<button>`" and "this will cause a hydration error."
**Impact**: Invalid HTML per spec. Screen readers and assistive tech may misinterpret the interactive region. Click behavior can be unpredictable (clicks on the inner button may also fire the outer button's onClick).
**Fix**: Change the outer `<button>` to a `<div role="button" tabIndex={0}>` or restructure so the delete button is not nested.

### Bug #3 -- Missing `playback_progress` table (MAJOR)

**Severity**: Major
**Location**: `src/services/playback.js` -> `getRecentProgress()`
**Description**: Every page load triggers a Supabase query against `public.playback_progress`, which does not exist. Returns 404 and logs `Could not find the table 'public.playback_progress' in the schema cache`. Error fires twice per load.
**Impact**: Console noise on every navigation. The `progressMap` feature (playback progress bars on podcast rows) is non-functional. The error is caught gracefully -- the app does not crash -- but it represents dead code referencing an unmigrated table.

### Bug #4 -- No error state for invalid KB/podcast UUIDs (MINOR)

**Severity**: Minor
**Location**: `src/pages/KnowledgeBase.jsx`, `src/pages/PodcastDetail.jsx`
**Description**: Navigating to `/kb/nonexistent-uuid` or `/podcast/nonexistent-uuid` triggers Supabase 400 errors ("invalid input syntax for type uuid") and silently redirects to home. No user-visible error message like "Knowledge base not found."
**Impact**: If a user has a stale bookmark or a bad link, they are silently dumped to the home page with no explanation. 12-16 console errors fire per bad navigation.

### Bug #5 -- Discover page fails to load categories (MINOR)

**Severity**: Minor
**Location**: `/discover` route, likely the edge function behind category loading
**Description**: The Discover page renders its header and layout correctly but shows an error banner: "Failed to load categories: network error (Failed to fetch)" with fallback text "No shows found."
**Impact**: The entire Discover page is non-functional. This may be an edge function deployment issue or a CORS problem with the Podcast Index trending endpoint.

### Bug #6 -- Sidebar hours stat inconsistency with hero (COSMETIC)

**Severity**: Cosmetic
**Location**: Sidebar footer vs. Home hero
**Description**: Sidebar shows "64.4 h indexed" (one decimal place). Hero shows "64 hours" (rounded integer via `Math.round(totalHours)`). Both compute from the same `podcasts` array. Not a bug per se, but the slight numeric discrepancy (64 vs 64.4) could confuse observant users.

## UX Observations

1. **KB name truncation on detail page**: The test KB name "QA Test 1780677444277" renders as "QA Test 1780677444..." on the detail page -- the truncation is appropriate but the ellipsis placement could be better (currently mid-number).
2. **Profile page shows "Unknown" email**: Since auth is not fully wired, the profile page shows "Unknown" for email with a working "Sign out" button. This is expected for the current dev state.
3. **All 5 visible podcasts are "pending" status**: None are "ready" -- all show "pending" + "Audio" indicators, suggesting the processing pipeline has not been run on these episodes.
4. **Delete button on KB cards is opacity-0 until hover**: Good UX pattern, but the nested button HTML issue (Bug #2) undermines it.
5. **Sidebar keyboard hint shows Mac symbol**: The "Search or ask..." bar renders a hardcoded `⌘K` (Layout.jsx line 115: `<kbd>⌘K</kbd>`) regardless of OS. On Windows it should display `Ctrl+K`. The actual shortcut works via `Ctrl+K` (Layout.jsx line 28 checks `e.ctrlKey`), so the hint is misleading on non-Mac platforms.
