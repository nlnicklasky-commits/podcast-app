## Bugs & Issues

### CRITICAL

**BUG-D1: Missing `playback_progress` table in Supabase**
- **Evidence:** Console error on every page load: `"Could not find the table 'public.playback_progress' in the schema cache"`
- **Impact:** Playback progress saving/loading silently fails. Resume-from and completion features are broken. The `getRecentProgress()` call on the Home page also fails, preventing playback progress bars on the recent podcasts list.
- **Source:** `src/services/playback.js` queries a table that does not exist in the DB.
- **Fix:** Run a migration to create the `playback_progress` table, or remove/disable the feature code until the table exists.

**BUG-D2: Missing `kb_syntheses` table in Supabase**
- **Evidence:** Console error on every KB page: `"Could not find the table 'public.kb_syntheses' in the schema cache"` from `getSynthesis()` in `src/services/synthesis.js:38`
- **Impact:** The "Generate Synthesis" button is shown but will fail when clicked. Synthesis data cannot be stored or retrieved. The Synthesis tab's empty-state prompt renders, but the CTA is non-functional.
- **Source:** `src/services/synthesis.js` references `kb_syntheses` which is documented in CLAUDE.md schema but not created in the database.
- **Fix:** Run migration to create `kb_syntheses` table matching the documented schema.

### MAJOR

**BUG-D3: Nested `<button>` inside `<button>` HTML nesting violation**
- **Evidence:** React console warning: `"In HTML, <button> cannot be a descendant of <button>. This will cause a hydration error."`
- **Location:** `PodcastRow` component in `KnowledgeBase.jsx` — the entire row is a `<button>` (line 281), and the delete/remove button (line 327) is a nested `<button>` inside it.
- Same pattern in `KBCard` on Home page — outer `<button>` contains a delete `<button>`.
- **Impact:** Invalid HTML semantics. Could cause accessibility issues with screen readers and keyboard navigation. May trigger hydration errors in SSR scenarios.
- **Fix:** Change outer element to `<div role="button" tabIndex={0}>` or use event delegation instead of nested buttons.

### MINOR

**BUG-D4: Timestamps in transcript are not clickable/linkable**
- **Observation:** Transcript timestamps (0:00, 0:03, etc.) display as styled text but are not interactive. Clicking does not seek audio or generate a shareable link.
- **Impact:** Users cannot jump to a specific point in the audio from the transcript, despite timestamps being visually prominent. The `?t=` param works for highlighting but there is no UI to generate these links from the transcript.
- **Recommendation:** Make timestamps `<button>` or `<a>` elements that seek the audio player or copy a timestamped URL.

**BUG-D5: Speed control and progress features gated behind auth**
- **Observation:** The playback speed button (`1x/1.25x/1.5x/2x`) is wrapped in `{user && ...}`, making it invisible to unauthenticated users. Resume-from and completion indicators are similarly gated.
- **Impact:** Unauthenticated users get a bare audio player without speed controls. If the app is meant to be usable without login, these features are hidden.
- **Note:** This may be intentional (persist-to-server features need a user). The speed control itself does not require persistence and could be shown to all users.

## UX Observations

1. **Processing progress card always visible**: Even for ready podcasts that completed weeks ago, the "All done! 14:11 100%" card takes up significant vertical space. Consider collapsing this for ready podcasts or moving it to the Processing tab only.
2. **Transcript is a very long scroll**: 2,815 segments at ~30px each = ~84,000px of content. No virtualization, search, or jump-to-time navigation within the transcript. Performance may degrade for longer episodes.
3. **No "Process All" bulk action on KB page**: The Huberman KB has 20 pending episodes. Users must process them one by one from each detail page. A bulk action on the episodes list would save significant friction.
4. **Chat starter prompts are generic**: "What are the key takeaways?" etc. could be more contextual based on actual topics in the KB.
5. **Synthesis tab shows CTA despite underlying table being missing**: The UI renders the "Generate Synthesis" prompt, but clicking will fail because `kb_syntheses` table does not exist. This creates a broken user experience — the button appears functional but is not.
