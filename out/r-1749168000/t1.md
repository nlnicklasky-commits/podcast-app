## Bugs / Issues Found

### BUG-1: Missing `playback_progress` table (MAJOR)

**What:** The home page calls `getRecentProgress()` which queries a `public.playback_progress` table that does not exist in the Supabase schema cache. This fires on every page load and logs 2 console errors.

**Impact:** The playback progress bars on the Recent Podcasts list silently fail. No progress indicators are shown for any podcast. The app does not crash because the error is caught, but the feature is non-functional.

**Evidence:** Console error: `"Failed to load recent progress: Could not find the table 'public.playback_progress' in the schema cache"` -- logged twice during the test run. The `playback_progress` table is not documented in CLAUDE.md's database schema section, suggesting it was added recently but the migration may not have been applied.

**Source:** `src/services/playback.js` calls `supabase.from('playback_progress')`.

---

### BUG-2: Nested `<button>` inside `<button>` (MINOR)

**What:** React warns about invalid HTML nesting -- a `<button>` is rendered inside another `<button>`. This occurs in the KB card component on the home page, where the delete "X" button is nested inside the card's outer `<button>`.

**Evidence:** Console warning: `"In HTML, <button> cannot be a descendant of <button>. This will cause a hydration error."`

**Source:** `src/pages/Home.jsx` lines 286-312 -- `KBCard` renders the delete button inside the card button. The `e.stopPropagation()` on line 296 prevents functional issues, but the HTML is invalid per the spec and could cause SSR hydration errors if server-rendering is added later.

**Fix:** Change the outer KB card from `<button>` to `<div role="button" tabIndex={0}>` or restructure so the delete button is a sibling overlay.

---

### BUG-3: 404 on podcast artwork images (MINOR)

**What:** 74 resource load failures (HTTP 404) during the test session, all from external podcast artwork image URLs.

**Impact:** Broken images show as empty space in the UI. The `<img>` tags have no fallback `onError` handler, so failed images leave invisible gaps. However, during the show search test, all 12 artwork images loaded successfully (0 broken), so this issue primarily affects the home page's recent podcasts list where older/stale artwork URLs may have changed.

**Evidence:** 74x `"Failed to load resource: the server responded with a status of 404 ()"` in console. Zero broken images in the AddPodcastModal search results (fresh URLs from Podcast Index).

## UX Observations

1. **Modal height adapts to content** -- empty state is 215px tall, grows to fill 85vh when search results load. Smooth transition.
2. **Search is fast** -- Podcast Index API via edge function returns results in ~1-2 seconds. Episode loading took longer (~5-8 seconds) on first call, likely due to edge function cold start.
3. **Artwork images are consistently sized** (52x52px squares with rounded corners) and use `object-cover` for proper aspect ratio handling.
4. **The "All Transcript" button** is well-differentiated from "Add All" -- outlined style vs filled, making the distinction clear.
5. **Episode view subtitle** ("by The Agile Brand - Add episodes to your library") provides good context and clear CTA framing.
6. **No loading skeleton/shimmer** -- the search and episode loading states use a simple spinner. This is fine for the current speed, but if latency increases, skeleton loading would improve perceived performance.
7. **The "Recent" dropdown** appears above the button (bottom-full positioning), which is correct since the footer is at the bottom of the modal.
8. **Show cards in search results are not visually grouped** -- they flow as a flat list. For 12+ results, a brief "N results for 'technology'" count would add helpful context.
9. **Subscribe button** appears on each show card (SubscribeButton component) but was not tested for functionality in this run.
