# Gap Analysis: Podcast Knowledge Base App

**Date:** 2026-06-05 | **Sources:** 4 QA reports (t1-t4), CLAUDE.md, blackboard | **Total screenshots reviewed:** 90

---

## 1. Executive Summary

The app's core happy path -- searching podcasts via Podcast Index, adding episodes, viewing details and insights -- works reliably (42/42 pass in t1, all CRUD flows pass in t2). However, three missing database tables (`playback_progress`, `search_history`, `kb_syntheses`) and CORS misconfigurations on two Edge Functions (`semantic-search`, `podcast-discover`) block the semantic search, discover, and synthesis features entirely. Of 29 feature items across Phases 1-5, 20 are fully working, 4 are partially working, and 5 are broken or non-functional. The app is a solid MVP with a broken search/discovery layer.

## 3. Critical Bugs (P0)

### P0-1: CORS preflight failures on `semantic-search` Edge Function
- **QA IDs:** S-1 (t4), K-1 (t4)
- **Description:** The `semantic-search` Edge Function rejects CORS preflight `OPTIONS` requests from `http://localhost:5173`. Every transcript search query fails with: `"Access to fetch at '.../functions/v1/semantic-search' from origin 'http://localhost:5173' has been blocked by CORS policy"`.
- **Root cause:** Missing or incorrect CORS headers in the `semantic-search` Edge Function. Other Edge Functions (`podcast-search`, `podcast-episodes`) handle CORS correctly, so this is function-specific, not a global config.
- **Impact:** The app's primary value proposition -- searching across podcast transcripts with semantic similarity -- is completely non-functional. Affects: Search page transcript tab, Command palette `?` mode, any vector-search-dependent feature.
- **Confirmed by:** t4 screenshots `search-02` (CORS error inline), `search-10` (palette shows "No transcript matches" due to silent CORS failure).

### P0-2: CORS preflight failures on `podcast-discover` Edge Function
- **QA IDs:** D-1 (t4), Bug #5 (t2)
- **Description:** All 4 requests to `functions/v1/podcast-discover` fail with CORS preflight rejection. The Discover page shows only `"Failed to load categories: network error (Failed to fetch)"` and `"No shows found"`.
- **Root cause:** Same pattern as P0-1 -- missing CORS headers on this specific Edge Function.
- **Impact:** The entire Discover page is non-functional. Users cannot browse trending podcasts or categories.
- **Confirmed by:** t4 screenshot `search-06`, t2 route testing.

### P0-3: Missing `kb_syntheses` table in Supabase schema cache
- **QA IDs:** BUG-D2 (t3)
- **Description:** The `kb_syntheses` table is documented in CLAUDE.md's schema but does not exist in the database (or is not exposed via PostgREST). Every KB page load triggers `"Could not find the table 'public.kb_syntheses' in the schema cache"`. The "Generate Synthesis" button renders but clicking it will fail.
- **Root cause:** Migration not applied. Table is documented in CLAUDE.md but never created in the database.
- **Impact:** KB-level cross-podcast synthesis -- a core differentiating feature ("compare viewpoints, find agreements/disagreements, surface patterns") -- is broken. The UI misleads users by showing a functional-looking CTA that will error on click.
- **Confirmed by:** t3 console error from `src/services/synthesis.js:38`.

## 4. Major Bugs (P1)

### P1-1: Missing `playback_progress` table in Supabase schema cache
- **QA IDs:** BUG-1 (t1), Bug #3 (t2), BUG-D1 (t3)
- **Description:** `src/services/playback.js` queries `public.playback_progress` on every page load. The table does not exist. Produces 2 console errors per navigation.
- **Impact:** Playback progress bars on Recent Podcasts list are non-functional. Resume-from-position and completion tracking are broken. Console noise on every page load.
- **Confirmed by:** All three QA reports (t1, t2, t3) independently flagged this.

### P1-2: Missing `search_history` table in Supabase schema cache
- **QA IDs:** S-2 (t4)
- **Description:** `src/services/search.js:31` queries `public.search_history` on every `/search` page load. Table not exposed via PostgREST. Produces 6 console errors per search page visit.
- **Impact:** Search history feature is broken -- no recent searches shown, no search suggestions.
- **Confirmed by:** t4, 6 console errors per `/search` load.

### P1-3: Nested `<button>` inside `<button>` HTML violation
- **QA IDs:** BUG-2 (t1), Bug #2 (t2), BUG-D3 (t3)
- **Description:** The `KBCard` component (Home.jsx) and `PodcastRow` component (KnowledgeBase.jsx) render a delete/remove `<button>` inside an outer `<button>`. React warns: `"In HTML, <button> cannot be a descendant of <button>. This will cause a hydration error."` Also present on KB detail episode rows.
- **Impact:** Invalid HTML per spec. Screen readers may misinterpret interactive regions. Could cause hydration errors if SSR is added. Click behavior may be unpredictable.
- **Confirmed by:** All three reports (t1, t2, t3) flagged this independently.

### P1-4: No 404 page for unknown routes
- **QA IDs:** E-3 (t4)
- **Description:** Navigating to `/nonexistent-route` renders the sidebar layout with a completely blank main content area. No "Page not found" messaging, no redirect.
- **Impact:** Users hitting a bad link see a broken-looking page with no guidance.
- **Confirmed by:** t4 screenshot `search-15`.

### P1-5: Silent redirect on invalid KB/podcast UUIDs -- no error state
- **QA IDs:** Bug #4 (t2), E-1/E-2 (t4)
- **Description:** Navigating to `/kb/nonexistent-uuid` or `/podcast/nonexistent-uuid` triggers Supabase 400 errors and silently redirects to home. No user-facing error message. Non-UUID strings cause `"invalid input syntax for type uuid"` errors. Valid-format UUIDs that don't match records also silently redirect.
- **Impact:** Stale bookmarks or shared links fail silently. 12-16 console errors per bad navigation.
- **Confirmed by:** t2 screenshots `home-18`, `home-19`; t4 screenshots `search-13`, `search-14`.

## 8. Root Cause Analysis

### Root Cause 1: Missing database migrations (3 tables)

Three tables referenced in code do not exist in the Supabase schema cache: `playback_progress`, `search_history`, and `kb_syntheses`. Two of these (`playback_progress`, `search_history`) are not even documented in CLAUDE.md, suggesting they were added as code features without corresponding migrations. `kb_syntheses` is documented but the migration was never applied. This is the single most impactful root cause -- it breaks synthesis, search history, and playback progress features, and generates console errors on nearly every page load.

**Pattern:** Feature code was written and committed before the database migration was run. All three are likely in a single batch of recent work that was never deployed to the database.

### Root Cause 2: CORS misconfiguration on newer Edge Functions (2 functions)

`semantic-search` and `podcast-discover` both fail CORS preflight, while `podcast-search` and `podcast-episodes` work fine. The working functions were deployed earlier (v2) and are listed in CLAUDE.md; the broken functions are newer and unlisted. This suggests the newer functions were deployed without the CORS headers that the older functions include. Supabase Edge Functions require explicit CORS headers in the response -- the newer functions likely omit the `Access-Control-Allow-Origin` header or don't handle `OPTIONS` requests.

**Pattern:** Newer Edge Functions copied business logic but not the CORS boilerplate from older functions.

### Root Cause 3: Documentation drift

CLAUDE.md lists 6 Edge Functions but the app uses at least 7 (missing `semantic-search`). The Edge Functions table is stale. `playback_progress` and `search_history` tables are not documented. Phase 6 items (responsive design, export insights) are actually already implemented but not checked off. The documentation has not kept pace with development.

### Root Cause 4: No client-side input validation for UUIDs

Routes `/kb/:id` and `/podcast/:id` pass raw URL params to Supabase queries without validating UUID format. Non-UUID strings cause Supabase 400 errors. Valid-format UUIDs that don't match records trigger silent redirects. Both cases produce console errors and no user feedback.

## 9. Recommended Fix Priority

1. **Add CORS headers to `semantic-search` and `podcast-discover` Edge Functions** -- Effort: S -- Unblocks: semantic search (the app's core value prop), Discover page, Command palette `?` mode. Copy the CORS handling pattern from `podcast-search` or `podcast-episodes`.

2. **Run migration for `kb_syntheses` table** -- Effort: S -- Unblocks: KB-level cross-podcast synthesis. Schema is already documented in CLAUDE.md; just needs `CREATE TABLE`.

3. **Run migration for `playback_progress` table (or remove dead code)** -- Effort: S -- Unblocks: playback progress tracking on home page. Eliminates 2 console errors per page load. If the table schema is not finalized, remove the `getRecentProgress()` call instead.

4. **Run migration for `search_history` table (or remove dead code)** -- Effort: S -- Unblocks: search history feature. Eliminates 6 console errors per `/search` load.

5. **Add a 404 catch-all route** -- Effort: S -- Unblocks: proper error handling for unknown URLs. Add a `<Route path="*" element={<NotFound />} />` to the router.

6. **Add client-side UUID validation on KB/podcast routes** -- Effort: S -- Unblocks: clean error states for bad links. Validate UUID format before querying; show "not found" component instead of silently redirecting.

7. **Fix nested `<button>` HTML violation** -- Effort: S -- Unblocks: valid HTML, accessibility compliance. Change outer `<button>` to `<div role="button" tabIndex={0}>` in `KBCard` and `PodcastRow`.

8. **Add `onError` fallback for podcast artwork images** -- Effort: S -- Unblocks: graceful handling of 74+ stale artwork URLs. Add `onError` handler that sets a placeholder SVG.

9. **Fix sidebar keyboard hint to detect OS** -- Effort: S -- Unblocks: correct `Ctrl+K` hint on Windows instead of hardcoded `Cmd+K`.

10. **Update CLAUDE.md documentation** -- Effort: M -- Unblocks: accurate project state. Add missing tables, update Edge Functions table, check off Phase 6 items that are done, document undocumented features.

11. **Make transcript timestamps clickable** -- Effort: M -- Unblocks: audio-transcript linking. Wire timestamp clicks to seek the audio player.

12. **Sync search URL params** -- Effort: S -- Unblocks: bookmarkable/shareable search state.
